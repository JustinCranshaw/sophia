# Checked cited-page navigation — SOP28

Cited-page evidence retains Open page and adds numbered choices for current visible sections. The page header also has a Sections menu, so the person can choose another section without leaving the mounted page. An exact choice binds notebook, page, existing edit-range key, heading and content hash in memory. Duplicate headings are distinct; legacy title links require one unambiguous visible match. A changed/deleted target produces a notice instead of guessing. No persisted evidence/transcript schema, UI automation tool, navigation service or new IDs were added.

Page identity still resets on a different page/notebook. A fresh request UUID explicitly triggers navigation on the same mounted page. Direct navigation and page Undo clear old intent/feedback. During source editing the Sections chooser is disabled; any other request reaching that open editor is refused with “Finish editing, then choose the section again.” It is not deferred against old heading geometry. Done followed by a new choice works with unchanged headings. This preserves the existing editor rather than committing it to navigate.

`AppModel.follow` checks an existing notebook and listed on-disk page before opening. Native testing found that the old link-label helper independently recreated a missing notebook by constructing a store during redraw. It now reads the existing file through the same pure frontmatter parser, without a store initializer. An absent destination stays absent. Navigation does not call write_page or edit source; leaving an existing editor still has its documented save behavior.
